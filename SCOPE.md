# Scope

These skills are curated. Ideas are welcome and judged against the bar below.

## The bar

A change is considered when it clears both parts:

1. **Observed failure or evidence.** It describes something that went wrong in a real session (what you ran, what the skill did, what you expected), or it cites research that changes a rule. "It would be nicer if…" does not clear this part.
2. **Fits the toolkit.** It keeps the core builder- and framework-agnostic, keeps brand values in the brand profile, and is phrased as a checkable rule with its fix. If it can be checked by a script, it comes with a lint rule.

## What belongs elsewhere

- **One brand's preferences** go in that brand's `website-builder/brand.md`, not in the skills.
- **Build mechanics** for a builder (how to write pages, APIs, deployment) belong to that builder's tooling. Stack skills link to it.
- **New stack skills** are added for tools with official documentation and enough users that the rules can be tested on real sites. Today: Automatic.css, Etch, Bricks.
- **Positive style wishes** ("make it feel premium") are not accepted as rules. Research on agent instruction files found them unhelpful or harmful; see `docs/EVIDENCE.md`.

## Maintenance

Each skill carries a `last-reviewed` date. On review, rules that no longer hold are deleted, not overridden by a newer rule below them.
