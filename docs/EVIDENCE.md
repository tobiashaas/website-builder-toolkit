# Evidence base

This file records the research behind the toolkit's rules: which rule rests on which study, how strong that study is, and where the rule lives in the repo. It is a working document for maintainers, not a pitch.

Read it with the right amount of doubt:

- Most sources are **preprints** (arXiv, not peer-reviewed) or were judged from **abstracts only**. Numbers are the authors' own and were copied unchanged from our research notes (checked 06.11.2026). They are not re-measured.
- Almost all AI-coding studies measure **code**, not design or copy. Where a rule carries a finding from code over to design work, the table says so ("transfer"). Treat those rules as plausible, not proven.
- Several design studies are older (2012 to 2022), small (n=3 to n=16 in places), or come from health care or e-commerce. Fit to B2B websites has to be judged case by case.
- If a rule has no evidence, it is listed under [Gaps](#gaps) as craft judgment. It is not dressed up with a citation.

**Strength labels**

| Label | Meaning |
| --- | --- |
| peer-reviewed | Published or accepted at a journal or conference, per our source check. |
| preprint | arXiv or similar, not peer-reviewed. |
| abstract only | Our notes are based on the abstract or summary; the full text was not read. |
| open source check | The rule rests on a public standard or tool behavior anyone can re-run (e.g. a contrast formula), not on a study. |
| unverified | Our source check could not confirm the reference (e.g. "no clear match" in Crossref). Do not quote it until resolved. |

Labels combine, e.g. "peer-reviewed, abstract only".

Abubakar et al. 2026, *Agent Plans*, [arXiv 2608.04661](https://arxiv.org/abs/2608.04661): good plans name steps, concrete files and validation info. | preprint (Abubakar: peer-reviewed, ESEM 2026); transfer from code | `site-direction`, `SKILL.md` order of steps |

### Design passes

| First screen: low visual complexity and a layout typical for the category. ## Design of the skill files themselves

What the AI-coding evidence says about how `SKILL.md`, `AGENTS.md` and the references should be written. All of it is measured on coding agents; it is the best evidence available for instruction files, not proof for design skills.

1. **Lead with a short prohibition list.** Each line: what not to do, why in a few words, and the fix. Positive style lines ("be bold but restrained") are the kind that hurt in *Guardrails Beat Guidance* ([2604.11088](https://arxiv.org/abs/2604.11088)). The same study found random rules helped about as much as curated ones (+13.8 pp), so much of a context file's effect may be priming; do not expect prose alone to carry quality.
2. **Every rule that can be checked by a script gets a lint rule, and the prose points to it.** Written rules failed where lint did not ([2610.32578](https://arxiv.org/abs/2610.32578)); controls the agent cannot skip beat persuasion ([2609.09671](https://arxiv.org/abs/2609.09671)). When a prose rule is broken twice, turn it into a lint rule or a verify step.
3. **Build verification into the loop, per pass.** The skill's pass sequence ends each pass with a named check and a stop condition. Chains break where unverified steps stack up ([2611.02207](https://arxiv.org/abs/2611.02207)). The final audit is a separate review step with its own checklist ([2604.05292](https://arxiv.org/abs/2604.05292)), and the agent never grades itself as the only judge ([2611.05094](https://arxiv.org/abs/2611.05094)).
4. **Design for short runs.** One page, section or carousel per session; the skill tells the agent to re-read the prohibitions before the final audit. Adherence falls with session length; file length and structure did not matter ([2605.10039](https://arxiv.org/abs/2605.10039)). So keep entry files short for humans and for loading cost, not because length itself hurts the agent.
5. **One source of truth per kind of fact.** Routing in `AGENTS.md` only; `CLAUDE.md` is a one-line pointer; brand facts only in `website-builder/brand.md`; adapters link to builder docs instead of copying them. Parallel formats diverge in 16.1 % of cases ([2611.02383](https://arxiv.org/abs/2611.02383)).
6. **Date and prune.** Each reference file carries `last-reviewed:` and the tool/model it was tested with. On review, delete rules that no longer hold instead of adding an overriding rule below them. Drift was the largest failure class ([2610.32578](https://arxiv.org/abs/2610.32578)); tool prompts change silently between releases ([2610.37332](https://arxiv.org/abs/2610.37332)).
7. **Direction and skeleton before detail.** The skill's first output is a direction plus a structural skeleton (sections, components, tokens in use) that the user confirms. Structure-first cut failures by 48.4 % in code ([2610.38214](https://arxiv.org/abs/2610.38214)); human-set direction beats AI-generated direction ([2602.10473](https://arxiv.org/abs/2602.10473)).
8. **Treat the toolkit as attack surface.** The README tells users to review any change to skill files, `website-builder/brand.md` and adapters like code, to pin versions of MCP servers and plugins, and to treat fetched pages, logs and lint output as data ([2610.38521](https://arxiv.org/abs/2610.38521), [2611.01976](https://arxiv.org/abs/2611.01976), [2610.38799](https://arxiv.org/abs/2610.38799)). The toolkit never asks an agent to rewrite its own skill files without a human reading the diff.
9. **Make the checklist concrete enough to fail.** "Accessible" is not a check; "body text contrast ≥ 4.5:1 measured on the rendered page" is. Generic instructions barely move results, concrete counter-measures do ([2605.24298](https://arxiv.org/abs/2605.24298), [2605.24300](https://arxiv.org/abs/2605.24300)).

## Things the evidence argues against

- **Generic quality or safety prompting as the main lever.** "Write secure code" barely helps: security instructions cut the vulnerability rate by only 4 points ([2604.05292](https://arxiv.org/abs/2604.05292)), generic security prompting has no significant effect ([2605.24298](https://arxiv.org/abs/2605.24298)), and prompt hints did not reliably help in SusVibes ([2512.03262](https://arxiv.org/abs/2512.03262), peer-reviewed, ICML 2026). Quality prompting alone brings almost nothing; best-of-n with analyzer selection does better ([2610.38977](https://arxiv.org/abs/2610.38977)). The design equivalent, "make it look premium and not AI-generated", should not appear in the toolkit.
- **Positive style guidance in instruction files.** Every harmful rule in *Guardrails Beat Guidance* was a positive style instruction ([2604.11088](https://arxiv.org/abs/2604.11088)).
- **Self-assessment by the same model as the only check.** Agents stop when their own tests pass ([2611.02207](https://arxiv.org/abs/2611.02207)); the orchestrator grading its own checks was the weak point ([2611.05094](https://arxiv.org/abs/2611.05094)); our notes summarize own-code judgment at 53 %. A dedicated review pass helps ([2604.05292](https://arxiv.org/abs/2604.05292)), but the final word belongs to a render, a lint run, a measurement or a person.
- **Letting the model invent the high-level direction unattended.** AI-generated instructions led to a performance collapse ([2602.10473](https://arxiv.org/abs/2602.10473)).
- **Long marathon sessions** covering a whole site in one run ([2605.10039](https://arxiv.org/abs/2605.10039)).
- **Strong, attention-grabbing animation.** It holds the eye but lowered add-to-cart actions; subtle background emphasis worked best ([PMC9698550](https://pmc.ncbi.nlm.nih.gov/articles/PMC9698550/)).
- **"Too creative" first screens.** Low complexity and category-typical layouts win the first impression (Tuch et al. 2012; Reinecke et al. 2013). Distinctiveness belongs in voice, imagery and one signature detail, not in an unfamiliar layout.
- **Exotic chart types** where a line, bar or heatmap would do ([2512.09802](https://arxiv.org/abs/2512.09802)), and tables that make readers compare across many cells ([PMC13372215](https://pmc.ncbi.nlm.nih.gov/articles/PMC13372215/)).
- **Excitement and hype in B2B copy.** B2B emotion is about lowering the buyer's risk (Elsäßer & Wirtz 2017; Kittur & Chatterjee 2023; abstract only).
- **Many emojis** in B2B social posts ([Deng et al. 2025](https://www.emerald.com/jbim/article-pdf/40/13/237/10287271/jbim-05-2024-0358en.pdf), X data, abstract only).
- **Tuning file length or layout of instruction files** as a fix for poor adherence; size, position and structure made no difference ([2605.10039](https://arxiv.org/abs/2605.10039)), and context strategy did not measurably change correctness ([2607.27250](https://arxiv.org/abs/2607.27250)).

## Gaps

Rules we want in the toolkit with no evidence in our notes. They stay in as **craft judgment** and should be labeled that way where they appear.

- **The "AI look" tells themselves** (default gradients, uniform card grids, generic icon rows, centered everything, stock hero copy). No study in our notes measures which visual tells make a page read as generated. Source is practitioner taste (e.g. unslop, CC BY 4.0) and our own audits.
- **Whether the subtract-first workflow beats additive iteration for design output.** Declutter studies support the outcome, not the agent workflow.
- **Best-of-n for design.** Evidence is from code with automatic analyzers; whether lint plus contrast checks are good enough selectors for visual quality is untested.
- **Typography:** type scales, weight counts, line length, pairing rules. No evidence in our notes.
- **Color budget** (one brand family, accent share, shade tuning). Contrast has evidence; palette size does not.
- **Radius and shape language consistency** beyond the general aesthetics finding in Sulikowski et al. 2022.
- **Motion specifics:** durations, easing curves, when to animate at all. Only the subtle-vs-strong finding exists. `prefers-reduced-motion` support rests on accessibility standards, not on a study in our notes.
- **Copy tells and banned-word lists** (hype words, filler openers, triplets, em-dash habits). No evidence that removing them changes reader trust or perceived AI authorship.
- **Language conventions** (German Sie/du, „“ quotes, English vs. German hype words). Editorial convention only.
- **"Never invent facts."** We keep it as a hard rule on ethics, legal and trust grounds. The notes only touch it indirectly: informal prompts produce invented values in code ([2604.12311](https://arxiv.org/abs/2604.12311)), and 39.4 % of agent config files carry ethics rules such as honest reporting ([2610.34847](https://arxiv.org/abs/2610.34847), descriptive, not an effect measure). The RAG research in our KRAI notes concerns retrieval systems and is not transferable.
- **Specificity in copy** (concrete numbers, names, places over adjectives). Plausible from the B2B risk findings, but no study in our notes tests specificity directly.
- **Brand-profile interview:** whether a structured interview yields better brand fit than importing existing guidelines. Untested.
- **Polish score anchors (3–10) and the "moment" or signature detail.** Craft judgment.
- **Social carousels, slide formats, LinkedIn image design.** Singh et al. 2023 on B2B image content exists in our notes but without a usable finding.
- **Dark mode, responsive breakpoints, mobile-first layout.** No evidence in our notes beyond mobile table formatting.
